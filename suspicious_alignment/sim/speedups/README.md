# sim/speedups — do the Muon / HTMuon / Echelon speed-ups change the alignment outcomes?

Numpy simulations on Deng-style quadratics (model M2: `L(W) = ½ tr(Wᵀ A W)`, `W ∈ ℝ^{200×40}`,
dominant block `k = 20`). The note that reports the results is
`../../notes/research/sim_speedups.md`. Everything here is regenerated by the commands below
(fixed seeds; `numpy` 2.5, `matplotlib` 3.11, no torch).

```
export OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 MKL_NUM_THREADS=1
cd /home/user/htmuon/suspicious_alignment/sim/speedups

python3 test_port.py                                   # sanity checks of the ports        (5 s)
nice -n 10 python3 tune_lr.py                          # lr of the exact filters           (3.7 CPU-min)
nice -n 10 python3 exp_s2_alignment.py --ms 5 20       # S2, first half                    (~13 CPU-min)
nice -n 10 python3 exp_s2_alignment.py --ms 100 500    # S2, second half                   (~13 CPU-min)
python3 analyze_s2.py                                  # S2 tables + figures               (10 s)
nice -n 10 python3 exp_s1_static.py                    # S1a static transfer curves        (< 1 CPU-min)
nice -n 10 python3 exp_shadow.py                       # S1b + S3a along exact trajectories (~5 CPU-min)
nice -n 10 python3 exp_s3_frozen.py                    # S3b + S1c frozen high-alignment states (~3 CPU-min)
python3 analyze_shadow.py                              # S1b / S3 tables + figures         (10 s)
nice -n 10 python3 exp_precision.py                    # float32 / bfloat16 emulation      (~3 CPU-min)
nice -n 10 python3 exp_s2_wide.py                      # wide-layer robustness check       (~4 CPU-min)
python3 exp_s4_cost.py                                 # S4 flop table                     (< 1 s)
```

The long scripts use two worker processes and resume (existing result files are skipped; `--force`
recomputes).

## Optimizers (names used in all result files)

All spectral optimizers use the momentum rule of `muon.py` (`momentum.lerp_(grad, 1-β)`,
`update = grad.lerp_(momentum, β)`, β = 0.95, Nesterov) and the shape factor
`max(1, rows/cols)^0.5` (= √5 here).

| name | filter applied to the momentum matrix `M` | source |
|---|---|---|
| `sgd` | none, no momentum (Deng's SGD) | — |
| `sgdm` | identity, with the momentum rule above, no shape factor | — |
| `muon_exact` | `U Vᵀ` by SVD | — |
| `muon_ns5` | `zeropower_via_newtonschulz5(M, 5)` | `muon.py:5-31, 353-360` |
| `ht_exact` | `U S^p Vᵀ`, p = 0.125, by SVD | `muon.py:320-332, 425-432` |
| `ht_ns` | `zeropower_via_newtonschulz5(M,5) @ gram_root_1_16_via_newtonschulz(M, 0.125, 5)` | `muon.py:83-131, 435-444` |
| `ht_interval` | exact HT filter when `step % 5 == 0` (steps 5, 10, …), NS5 Muon otherwise | `muon.py:1645-1696` |
| `ht_avg` | reference only: `0.8·NS5(M) + 0.2·HT(M)` at every step (time-averaged filter of `ht_interval`) | — |
| `ht_stream`, `ht_stream_rk`, `ht_stream_r4` | `msign_generalized_ht_v2_stream_qr`, warm-started `V`, rank = full / k / 4 | `muon.py:1349-1485` |
| `ech_r{1,4,16,k}` | Echelon(r): tracked left frame (one subspace-iteration step per call), τ = 2 warm-started power-iteration steps | `echelon-lean` `HeadTail.lean`, `Cost.lean` |
| `ech_r*_ideal` | Echelon(r) with the exact top-r frame and τ = ‖T‖₂ exactly, i.e. the spectral filter `f(σ_i) = 1 (i ≤ r), σ_i/σ_{r+1} (i > r)` | — |
| `ech_r{4,k}_pol` | tracked Echelon(r) followed by one cubic step `1.5 O − 0.5 O OᵀO` | `Polish.lean` |
| `ech_r{4,k}_fro` | tracked Echelon(r) with τ = ‖T‖_F | — |

Approximations inherit the learning rate of the exact filter of their family (`muon_*`, `ech_*` ←
`muon_exact`; `ht_*` ← `ht_exact`).

## Port fidelity (deviations from the torch originals)

1. **Precision.** Default float64. The originals run NS5 in bfloat16 and the SVD, Gram-root and
   stream paths in float32. `exp_precision.py` re-runs the filters in float32 and in an emulated
   bfloat16 (float32 arithmetic with every operation result rounded to bfloat16, round-to-nearest-even;
   real bfloat16 kernels may accumulate differently).
2. **Not ported:** the 4-D (conv) branch, batched inputs, the distributed `all_gather`, weight decay
   (set to 0) and the auxiliary Adam group.
3. **Same constants:** NS5 coefficients (3.4445, −4.7750, 2.0315), Frobenius normalisation `+1e-7`,
   transposition when rows > cols; Gram root: `eps = 1e-6` added to `GᵀG` and after each square root,
   `round(log_{1/2}(power)) + 1 = 4` square roots for power 0.125, 5 coupled Newton–Schulz steps each,
   normalisation by the Frobenius norm; stream: `V₀ =` first k columns of `I_n`, `eps = 1e-8`,
   `sigma = clamp_min(diag(UᵀMV), 0)`; interval: counter incremented before the test, `start_step = 0`.
4. **Echelon.** The Lean repository contains no reference implementation (`py/ortho.py` is cited in
   `Cost.lean` but absent), so `Echelon` is written from the Lean definitions (`htDir`, `tail`,
   `cubicStep`) and the operation list of `Cost.lean` (`H = UᵀX`, `U(P − H/τ)`, `XHᵀ` + QR for the next
   frame, power iteration for τ). Choices that are ours: the frame is on the LEFT (rows, dimension 200)
   as in the task statement, although `Cost.lean` puts it on the short side; the frame used at step t
   was computed from `M_{t−1}` (one step of lag); first frame = `QR(M MᵀQR(MΩ))` with Gaussian `Ω`;
   τ from 2 warm-started power-iteration steps (a slightly low estimate; the measured ratio
   τ/‖T‖₂ is recorded); same shape factor as Muon.
5. **No torch on this machine**, so the ports could not be compared numerically with the originals;
   `test_port.py` checks them against scalar models and exact limits instead.
